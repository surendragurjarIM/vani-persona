Voice AI Hackathon 2.0 · PS04 Persona Design · Build log · updated 10 Oct 2026

VANI that sounds right for each seller, and changes when the call does

Before each call we generate a persona spec for the seller from their data and their audited call history. Every setting carries a reason, evidence and a confidence. The calls run on Sarvam Voice Agents: six VANI agents share one prompt, and each seller's persona arrives as 17 variables. During the call VANI detects frustration, confusion, interest, rush and language switches, changes delivery at the next turn, and logs every switch on the platform.

Two findings that shaped the design: language IDs on 1–2 word replies are unreliable (so a language switch needs 2 utterances of 3+ words), and Sarvam rate-limits at about 2 parallel chat calls (so the detector backs off and retries).

Guardrail built into the hook

The opening hook states the real reason for the call, which the lead bucket fixes (PIM/PAM → explored paid services, PUA/OLP → checked buy leads). So the persona cannot pick a flattering but false hook. It only chooses how to frame the true reason, how long the opening runs, and how it sounds. Prices come verbatim from the fact sheet. Today the bot quotes both ₹30,200 and ₹32,000, so the locked sheet fixes that.

17 persona variables per call

True call reason, opening style, language mix and register, tone, turn length, personal details, call history and audit, objection order, switch sensitivity, regional language, best callback window. Filled per seller from the generator via campaign cohort, on-start hook, test call or web session.

Live switch decided in code

On a turn that looks like a change, the agent calls update_persona_mode, a Python tool running inside Sarvam. It fuses the LLM's guess with the Hinglish lexicon mined from past calls, applies a fixed priority (do-not-call, frustration, rush, unavailable, confusion, interest) and a two-turn cooldown, lowers the frustration threshold for sellers called 4+ times, and returns the next reply's mode. Each switch is written to live_switch_log, which reaches the call results. Runs in 3 to 18 ms; nothing leaves Sarvam. The tool sees the words, not the audio.

Facts locked

Price written in words and digits so it is never rounded. The platform model first said ₹32,000, the old bot's wrong figure, and now says ₹30,200. Meetings count as fixed only on an explicit yes to a day and time.

Persona Service · console · board

Persona Service

FastAPI next to Sarvam: /persona, /route, /onstart hook, campaign push (1,000 sellers per request, do-not-call excluded), instant call, /webhooks/sarvam → results DB and review queue. Nightly job regenerates all personas in about 3 minutes. 15 tests; Docker image.

Demo console

Pick any of 149,363 sellers, see the persona with reasons and evidence, and talk to the routed VANI agent in the browser through Sarvam's Web SDK. The API key stays on the server: a proxy forwards only VANI session requests.

Board on Sarvam

VANI · Persona Performance: connected calls, outcome by persona agent, calls with live switches, and a recent-calls table with persona, language, signals, switch summary and slot. Reads the platform's own call data.

Audited data, used directly

Objection playbook

9 situations (busy, seller gives a time, price, not interested, out of station, who-are-you/bot, already met, bad experience, send details). Each comes with the evaluator's suggested reply from real mishandled calls: 3,207 audited gaps.

Per-seller history

5,375 sellers have audited gaps on their own calls. R-22 lowers that seller's threshold for the signal VANI missed before and adds "never repeat the pitch" when the audit caught that.

Detector labels

Evaluator reasons label 2,986 seller turns. They tuned the keyword list, set per-signal fusion, and give the live switch-timing metric.

Manual feed · built in for your team

Your reviewed calls outrank everything automatic

1 · ListenYour team reviews calls (transcript or recording) and hears tone that text misses.
2 · Log the gapOne row in manual_gaps.csv: seller said, VANI said, should have said, signal, tone heard.
3 · Set the fixAny spec setting, e.g. live_adaptation.thresholds.rush = 0.4, for a seller, a segment, or all; priority 1–5.
4 · Ingestpython -m manual.ingest validates the rows; recordings are transcribed with Saaras batch and speaker separation.
5 · ApplyPersonas regenerate with the overrides marked manual:<reviewer> at high confidence. Live thresholds, guardrails and detector examples update too.

Tested end to end with the template rows: one seller, one segment and an all-seller guardrail were each applied and tagged. Templates and instructions: vani-persona/manual/.

Open points

Telephony for campaigns

The workspace has no telephony connection yet, so it can't dial at scale. Test calls to verified numbers and browser sessions work now. Campaigns need a connection (Exotel, Twilio, Plivo or a number rented from Sarvam); the Persona Service already pushes cohorts.

Confirm the price

The old bot quoted both ₹30,200 and ₹32,000. VANI uses ₹30,200 + GST a year (about ₹4,000 + GST a month); IndiaMART should confirm it.

Guesses to test

Voice gender and regional language have no past-call evidence, so they are low-confidence choices. Pace can't change mid-call on this plan, and a code tool gets no audio; switches change wording, length, tone and language. Tone of voice comes from the manual feed's tone_heard column.
