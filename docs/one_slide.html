3 · Workflow

Data · 149k sellers, 269k calls, 278k audited evaluations

Persona generator · 23 evidence-cited rules + manual overrides (top priority)

Persona Service · routes each seller to 1 of 6 voice agents + 17 variables (cohort / on-start hook / web SDK)

Sarvam Voice Agents · Saaras STT → platform LLM → Bulbul v4 voices, per-language voice on switch

Live switch · Python code tool on Sarvam: LLM guess + Hinglish lexicon, fixed priority, 2-turn cooldown → next-turn mode + switch log

Learn · call-end webhook → Board + review queue → next night's personas

Offline rationale + detector tuning: sarvam-105b-conversations.

Switch log written by the code tool on Sarvam: turn 2 · confusion "kya bola? samjha nahi" (LLM + keywords) → simpler words · turn 3 · rush "busy hoon… jaldi bolo" → one line, two slots · close: "kal shaam chhe baje, dukaan par"

One-slide summary for PS04. Left: a real generated persona spec for seller 98255184, each setting tied to seller data and an evidence ID. Middle: the past-call evidence (meeting-fix rates, 95% CI, stratified) and the signal detector's measured accuracy. Right: the workflow, from IndiaMART data through the persona generator and Persona Service into six Sarvam Voice Agents. Mid-call, a Python code tool running inside Sarvam decides each switch: it fuses the LLM's guess with the Hinglish lexicon mined from past calls, applies a fixed priority and a two-turn cooldown, changes language when needed, and writes a structured switch log that reaches the call results. A code tool sees the words, not the audio, so detection is text plus seller history. Call results flow back to improve tomorrow's personas.
